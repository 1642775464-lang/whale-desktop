## 一、本片目标

让桥从「能应答但被动」变成「**能主动推、能写回去**」。完成后：

- 两个 SSE 端点可推实时数据，断线能续传（`Last-Event-ID`）；
- 22 条路由**全部落地**（本片补齐剩余 17 条），`GET /whale` 的 `implementedCount` 应等于 22；
- `/whale/hud` 返回全量快照，`/whale/hud/events` 推增量；
- 能拉起 / 关闭 / 查询小窗进程；
- 能向真会话发消息、发斜杠命令、切会话、切模型、中断、唤醒历史会话、应答审批、执行宿主侧动作；
- 2 秒心跳重算速度并推送。

**用户已拍板的四处决策（m01849「按你倾向的来」）**：

| 编号 | 决策 | 落地 |
|---|---|---|
| S3-D1 | `/whale/send` 的运行中行为 | 空闲 → `followup`；运行中默认 `followup`（等于排队到下一回合）；显式 `mode:"steer"` 走 `steer` 且照宿主守卫，非运行态拒掉（`session/steer-unavailable`）。返回体带 `{queued:boolean}` |
| S3-D2 | `/whale/approval` 的应答机制 | 桥挂 `approval/request` **瀑布监听器**，用「**无人应答时接管**」语义：先 `next()` 让别人处理，仅在无人应答时由桥补答案（`allowed-once` / `rejected` / `cancelled`），不抢宿主 UI 的答 |
| S3-D3 | `/whale/models` 数据源 | 本片按「探测不到就返回空 + 明确 `reason`」降级交付；探测路径作为待办记入 STATUS，不阻塞本片 |
| S3-D4 | SSE 心跳载荷 | 推轻量 `{kind:"tick", at, sessions:[{sessionId,tokPerSec,contextUsed,contextWindow}]}`，只含随时间变化的字段；全量快照仍走 `/whale/hud` |

## 二、新增文件（8 个源文件 + 4 个测试文件）

### 源文件（8 个）

| 文件 | 职责 | 行数预算 |
|---|---|---|
| `whale-bridge/lib/sse.mjs` | SSE 广播表：注册/注销客户端、`Last-Event-ID` 续传、环形缓冲、心跳写入、客户端计数 | ≤300 |
| `whale-bridge/lib/sse-buffer.mjs` | 推送事件的环形缓冲（有界，防内存无限增长）+ 按 id 取「之后的事件」 | ≤300 |
| `whale-bridge/lib/windows.mjs` | 小窗进程表：spawn（`delete ELECTRON_RUN_AS_NODE` + `--no-sandbox`）、存活判定、按 pid 关闭、复用 | ≤500 |
| `whale-bridge/lib/panel-data.mjs` | 把折叠器数据投影成 `/whale/panel` 的 `messages` / `todos`（接上切片 1 留的空位） | ≤300 |
| `whale-bridge/lib/handlers-slice3-read.mjs` | 8 条 GET：`/whale/events`、`/whale/windows`、`/whale/follow`、`/whale/models`、`/whale/approval`、`/whale/hud`、`/whale/hud/events` | ≤500 |
| `whale-bridge/lib/handlers-slice3-write.mjs` | 9 条 POST 的注册与参数校验外壳，转发到 `host-actions.mjs` | ≤500 |
| `whale-bridge/lib/host-actions.mjs` | 宿主写操作薄封装：send / command / activate / model / abort / resume / approval / action | ≤500 |
| `whale-bridge/lib/approval-bridge.mjs` | 审批瀑布挂载与「无人应答时接管」逻辑、挂起请求列表 | ≤300 |

**为什么这么拆**：
- `sse.mjs` 与 `sse-buffer.mjs` 分开——缓冲是纯数据结构（可脱离网络单测），广播表要碰 `res` 流。
- `host-actions.mjs` 与两个 handlers 文件分开——前者是「怎么让宿主做事」，后者是「HTTP 长什么样」，改动原因不同。
- `approval-bridge.mjs` 单独——审批是**瀑布拦截**而非普通读写，语义特殊，且要与 `host-actions` 的「查询挂起列表」分开。

## 五、验收口径（实测，不靠推断）

| 项 | 通过标准 |
|---|---|
| 闸门 | 六道全过，跳过 0 道 |
| 单测 | 全绿，含切片 1/2 既有 115 个不回归 |
| **C1** | `GET /whale` 返回 `routeCount === 22` 且 `implementedCount === 22` |
| **C2** | 只监听回环：非回环 Host 头被 403 拒（用伪造 Host 头实测） |
| **C3** | `GET /whale/events` 返回 `content-type: text/event-stream`；灌入事件后**1 秒内**收到帧（实测计时） |
| **C4** | `/whale/hud` 的 `totalOutput` 与折叠器四桶一致 |
| **C5** | `contextUsed` 等于 `pressureFrom(末条 usage)`，对照已实测样本 93271 |
| **C6** | `tokPerSec` 与「最近 8 秒增量 ÷ 8」一致（±10%） |
| **C7/C8** | `/whale/open` 在 `whale-window/` 尚未实现时**返回明确错误而非崩溃**（本片拿不到真小窗，故验「降级路径」）+ `/whale/windows` 形状正确 |
| **C11** | 无活跃回合时 `POST /whale/abort` 返回 409 且不误伤（`keepInbox: true`） |
| **C13** | 密钥扫描无命中（闸门 4 已覆盖） |
| 续传 | 带 `Last-Event-ID` 重连能补到断线期间漏掉的事件；id 超前时退化为「从头推」而非报错 |
| 心跳 | 2 秒一次 `{kind:"tick", ...}`；无客户端时**不产生开销**（不写、不计算） |

> **C7/C8/C12 的诚实说明**：这三条依赖 `whale-window/`（切片 5）。本片**无法**端到端验「真拉起小窗」，只能验「进程管理模块本身正确（用假 exe 路径）+ 失败路径明确报错」。真实验收留到切片 5 完成后回补。这一点必须在汇报里写清，不能含糊。

## 六、风险

| 风险 | 应对 |
|---|---|
| SSE 长连接拖住 `server.close()` | `close()` 已有 `closeAllConnections()`；额外把 SSE 客户端在 dispose 时显式 end |
| 环形缓冲无界导致内存增长 | 缓冲**必须**有上限（定 500 条），超出丢最旧；单测证明有界 |
| 审批瀑布「无人应答时接管」可能挂住宿主回合 | 桥只在**明确挂起**且超时才补答案；不在无挂起时介入。超时上限定 30 秒 |
| `spawn` 在本机沙箱被拒 | 进程管理模块用可注入的 `spawnFn`，单测注入假实现；真 spawn 只在验收时试 |
| `--no-sandbox` 与 `ELECTRON_RUN_AS_NODE` 漏处理 | 作为 `windows.mjs` 的**显式断言**写进单测（检查 args 与 env） |
| 22 条一次补齐，改动面大 | 分两批提交：先「只读 8 条 + SSE」，再「写操作 9 条」；每批都过闸门 |
