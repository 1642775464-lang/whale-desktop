# 切片 6 范围声明：页面内小鲸鱼按钮

> 依据：步 3「AI 拟范围、用户确认」。**未确认前不动任何代码。**

---

## 一、这一片要交付什么

在 DSH 页面**右下角**放一枚 40×40 的小鲸鱼按钮。单击它，**同时**拉起悬浮条与小窗。

| 项 | 内容 |
|---|---|
| 产物 | `whale-bridge/lib/client.js`（客户端半侧）+ `whale-button/`（说明与产物） |
| 挂载点 | `shell.overlay` 槽（PRD F8 指定） |
| 位置 | 右下角浮层，40×40 圆形，描边 `rgba(120,130,200,.30)` |
| 图标 | 复用 `whale-hud/renderer/favicon-whale.svg` 同一枚鲸鱼 |
| 单击行为 | `POST /whale/open` 拉起悬浮条，`POST /whale/open` 拉起小窗 |

---

## 二、代码放哪：**沿用已拍板的归属决策**

《轻量架构草案》§5.4 已经拍过这个板，本片**不重新决定**：

> Cordis 的客户端半侧插件必须与宿主插件**同包声明**（`client.js` 要在 `package.json` 里声明为客户端入口）。
> 决策：按钮代码物理上放 `whale-bridge/lib/client.js`；`whale-button/` 目录不重复实现，只放说明与产物。

理由：避免同一份代码两处维护。代价是目录名与实际位置不完全对应，**架构草案已显式记录此偏离**。

## 三、技术形态（已实测确认，非推测）

```kv
客户端入口: package.json 的 exports["./client"] + dsh.client{platform:web, immediately:true}
模块注册: window.__ModuleLoader__.load({id: "<包名>", factory(require){...}})
槽位注入: factory 里 inject: ["slots"]，ctx.slots.inject(slot, cb) → ctx.slots.register({name,id,order}, Component)
React: 从模块表 require("react")，不额外装
```

**一条命门**：`shell.overlay` 这一层是 **click-through** 的（宿主原文：`The layer itself is click-through — entries opt back into pointer events`）。
所以组件的根节点**必须自己写 `pointerEvents: 'auto'`**，否则按钮看得见、点不动。
已在本机同槽位的 `dsh-agnes-image` 里实测确认就是这个写法（其 `client.js:563`）。

## 六、验收判据（机器可判）

| 编号 | 判据 | 怎么验 |
|---|---|---|
| E1 | 按钮出现在页面右下角 | 探针读 DOM 的 `getBoundingClientRect()`，比对视口右下角 |
| E2 | 按钮是 40×40 圆形 | 读 rect 尺寸 + `borderRadius: 50%` |
| E3 | 图标是那枚鲸鱼 | 断言 svg 的 path 与 `favicon-whale.svg` 同一份 |
| E4 | 单击真的拉起悬浮条 | 点前后 `GET /whale/windows` 比对，悬浮条 pid 出现 |
| E5 | 单击真的拉起小窗 | 同上，小窗 pid 出现 |
| E6 | 能点动（不被浮层吞掉） | `document.elementFromPoint(按钮中心)` 命中按钮自身 |
| E7 | 不破坏宿主页面 | 控制台无报错、宿主原有元素仍在 |

**E6 是这一片最容易失败的一条**——`shell.overlay` 是 click-through 层，忘了写 `pointerEvents: 'auto'` 时按钮看得见、`elementFromPoint` 却返回下层元素。

## 七、诚实边界（先说清，不做事后解释）

| 项 | 说明 |
|---|---|
| 视觉细节 | 按规范给的 40×40 / 圆形 / 描边取值，但**深浅色主题下的实际观感需你目视确认** |

| 两个窗口都拉起 | 若宿主对同一次点击有防抖，可能只拉起一个——**待实测**，若发生我会如实报告 |
