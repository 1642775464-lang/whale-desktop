## 二、已完成的研究（决定怎么做）

### 2.1 模型目录为什么是空的 —— 找错了服务

桥的 `listModels()` 先找 `models` 服务，找不到就退回扫会话事件。
**宿主根本没有 `models` 这个服务**（用宿主自己的服务目录查证过）。
真正的模型目录在 **`llm` 服务**上：

```kv
listProviders: () => LlmProviderInfo[]            # 列出 provider
listModels: (provider) => LlmModelInfo[]          # 列出该 provider 的模型
resolveModelInfo: (provider, model) => ...        # 含 reasoningEffort 等详情
```

**这就是 `/whale/models` 一直返回 0 的真因** —— 不是「宿主没暴露」，是我找错了地方。

### 2.2 思考强度（reasoningEffort）

`reasoningEffort` 是模型级配置（`LlmCallConfig` 的字段，各模型可选值不同）。
所以浮层要先拿到**当前模型的**可选 effort，不能写死。

**取不到就只显示当前值，不编造档位** —— 与「不硬编码模型名」同一条纪律。

### 2.3 权限档位不止三个

宿主 `permission` 命令报的可用档位是：
`read-only / workspace-write / danger-full-access / auto`（4 个，含 `auto`）。
而小窗现在只循环前 3 个 → **`auto` 选不到**。浮层要列全部 4 个。

### 2.4 真上传走哪条路

宿主 `fileUploads` 服务：
```kv
upload: (agent, request, signal) => FileUploadValue   # @{ Remote }
uploadStream: (...) => FileUploadValue
```
这是「＋ 真能上传」的通路。
