## 一、这份东西是什么

一个悬浮在桌面上的**豆包式窄窗**，里面跑的是**真的 DSH 会话** —— 与主窗同一个会话、同一条消息流。在小窗里发的消息，就是主窗里发的消息。

**一句话定位**：把 DSH 的对话界面从浏览器里搬出来，变成一扇常驻桌面、随时能说话的窄窗。

---

## 二、它和悬浮条的分工

| | 悬浮条（Whale HUD） | 小窗（Whale Window） |
|---|---|---|
| 角色 | **状态栏** —— 看 | **对话窗** —— 用 |
| 尺寸 | 560 × 52 | 460 × 678（内容） |
| 位置 | 顶边居中，固定 | 屏幕右侧居中，可拖可缩放 |
| 内容 | 五个状态元素 | 完整会话界面 |
| 能否输入 | 否 | 是 |
| 进程 | 独立 Electron | 独立 Electron |

**两个独立进程是刻意的**：

- 关掉悬浮条不该影响小窗，反之亦然
- 同一进程里做多窗会让「退出」语义变得含糊（关哪个？）
- 单实例锁、userData 目录、托盘都要各自独立

两者共用同一个桥（`127.0.0.1:19387`），数据源一致。

## 三、功能需求

### F1 窗口形态（P0）

| 项 | 要求 |
|---|---|
| 尺寸 | 内容 460 × 678；窗口 492 × 710（含四周 16px 投影边距） |
| 边框 | 无边框（`frame: false`） |
| 圆角 | 18px，由 CSS + 透明窗口共同实现 |
| 阴影 | CSS `box-shadow`（**不是**原生 `hasShadow`） |
| 置顶 | `setAlwaysOnTop(true, 'floating')`，可切换 |
| 任务栏 | 不出现 |
| 全屏 | 不占（`fullscreenable: false`） |
| 可缩放 | 是（`resizable: true`） |
| 位置记忆 | 存 `window-state.json` |

**尺寸口径（务必看清，这里踩过）**：

- 「内容」= 布局真正能用的那块矩形
- 「窗口」= 内容 + 四周 `SHADOW_PAD`（撑出投影空间），CSS 再用等量 padding 收回
- **缩放只作用在内容上，且只在一个地方施加**（`scaledContent()`）

| | 内容 | 窗口 | 相对原始 |
|---|---|---|---|
| 原始 | 380×560 | 412×592 | 1.00 |
| 第 1 次 ×1.1 | 418×616 | 450×648 | 1.10 |
| 第 2 次 ×1.1 | **460×678** | **492×710** | **1.21** |

```
SHADOW_PAD = 16
CONTENT_SCALE = 1.1
SCALE_TIMES = 2
```

**两个必须避开的坑**：

1. 不要对**窗口**尺寸乘缩放系数 —— 边距会被一起放大，比例反而是错的
2. 不要把系数施加两次。曾在 `scaledContent()` 之后又让 `toWindowSize()` 乘一遍，实际变成 1.1³ ≈ 1.33，实测可见内容 506×746 才发现。**`toWindowSize()` 只负责加边距。**

**记忆值存的是窗口尺寸**，所以只在「没有记忆值」时用默认内容尺寸换算，不能反过来拿记忆值乘系数 —— 否则用户每重启一次小窗就被放大一次，几次后撑满屏幕。

### F2 顶栏（P0）

2026-10-04 重排（用户裁定）：**删掉「语音通话 / 麦克风 / 屏幕共享」三个占位按钮**。

| 位置 | 元素 | 说明 |
|---|---|---|
| 左 | `−` 最小化 | |

| 右 | `⚙` 齿轮 | 侧边工作台 |
| 右 | `☰` | 更多 |

**顶栏本身就是拖拽区**（无边框窗口需要渲染层把鼠标位移交给主进程）。

**图钉图标的注意事项**：整枚图标是**描边画法**（`fill: none` + `stroke: currentColor`），只有带 `r` 的 `circle` 才被填成实心点。

> **v2（当前）用真图钉剪影**：顶部一条宽横帽先定下「这是图钉」，下面才是梯形身和针。
>

### F3 会话标题行（P0）

三个元素：`会话标题` + `同源会话` 角标 + 副标题行。

**「同源会话」角标的意义**：明确告诉用户「这扇窗里的对话就是主窗那个会话」，消除「小窗是另一个会话吗」的疑虑。

### F4 消息流（P0）

| 项 | 行为 |
|---|---|
| 发送 | Enter 发送，Shift+Enter 换行 |
| 乐观渲染 | 消息立刻上屏，同时真的进入会话 |
| 排队 | 回合正在跑时发的消息**排队**（`mode: "queue"`），等当前回合结束再执行 |
| 中断 | 回合运行中发送键变**红色方块**，点它中断 |
| 自动重连 | SSE 断线自动重连（1s → 15s 退避）；切走窗口再切回也会重连 |

> **排队不是失败** —— 是豆包式的排队语义。

> **中断有护栏**：打的是**这个会话正在跑的 agent**。桥侧只有在明确探测到有活跃回合时才会真的取消，避免误伤。

### F9 切换会话（P0）

顶栏 `☰` → **项目** → 「会话」区，列出全部会话（含历次落盘的），每行右侧有状态标签：

| 标签 | 含义 | 点击后 |
|---|---|---|
| **当前** | 就是现在小窗打开的会话 | 无操作 |
| **可切换** | 已在宿主内存里的会话 | 立刻切过去 |
| **历史** | 只在磁盘上，宿主还没加载 | 先唤醒，成功后自动切 |

点「历史」时标签会变成 **「唤醒中 3s」** 这样带秒表的倒计时。

- 唤醒**失败**时标签还原，并弹出真实原因（例如会话文件已不存在）
- 唤醒会**真的在宿主里打开这个会话**，属于有副作用的操作
- 唤醒后的会话会一直留在宿主内存里，之后能秒切

> **v2 变更**：上游写「约 20 秒」，并注明「宿主行为，不可控」。本轮实现由**桥直接读落盘事件流**渲染历史会话，
> 不再把「唤醒」当作前置条件，因此该条改为：**历史会话立即可读**；若用户点击「切到该会话」需要宿主加载，
> 才进入「唤醒中 Ns」状态。这条变更使 B10 的验收不依赖宿主加载耗时。

### F12 窗口状态记忆（P1）

存 `window-state.json`，含位置、尺寸、置顶状态。

**位置有效性判据**：与任一显示器工作区的**交集面积 ≥ 窗口自身的 25%**。

- 不用「完全包含」：窗口允许略微超出边缘（用户故意贴边），全包含判据会把这些合理位置判成无效、反复重置
- 不用「左上角在屏幕内」：左上角在屏幕内但窗口 90% 在屏幕外的很常见（拖到边缘），那种位置对用户没意义

**写盘策略**：拖动/缩放高频触发 `move`/`resize`，故做 **400ms 防抖**；但**退出时立即补写一次** —— 否则「拖完马上关」的最后一次位置会丢。

### F13 崩溃兜底页（P1）

连续崩溃超过 3 次后加载。提供「再试一次」按钮。文案必须诚实说明发生了什么，不使用模糊措辞。

## 四、数据来源

```
DSH 会话事件流
      ↓  桥订阅 session/event 并折叠（保留最近 40 条渲染事件）
桥的 sessionFold
      ↓  GET /whale/events（SSE 实时事件流）
小窗渲染
```

**与 HUD 折叠的差异**：小窗只要最近 40 条**渲染**事件；HUD 要**全部 usage** 事件的聚合，所以 HUD 侧不设 tail 限制（但做了水位去重）。

### 4.2 渲染层通道

`preload.cjs` 只暴露一条受控通道，**不开放 node**：

```js
window.whale = {
  window(action),   // minimize | hide | close | toggle-pin | state | physical | resize
  drag(dx, dy),     // 无边框拖动
  log(msg),         // 渲染层日志落盘
  onTray(handler),  // 主进程 → 渲染层指令（只回传白名单字符串 'reload'）
}
```

> `onTray` 只回传白名单字符串，不把原始 event 交给渲染层（避免暴露 `sender` 等对象）。

## 五、技术约束（改代码前必读）

### 5.1 必须带 `--no-sandbox`

开 Chromium 沙箱时 GUI 初始化阶段直接崩 `0x80000003`（STATUS_BREAKPOINT），**存活仅 15~20ms，连 `main.cjs` 的模块体都执行不到**。

### 5.2 必须显式 `app.setPath('userData', ...)`

让 Electron 去解析**默认** userData 路径会让进程**原生崩溃** —— 退出码 `-36861` / `0xFFFF7003`，不抛 JS 异常、try/catch 接不住、日志来不及写。

表现就是「小窗双击没反应」：桥的 `/whale/open` 返回了 pid，但进程已死。

> 顺带的好处：状态与日志跟着工程走，不再散落在 `%APPDATA%`。

### 5.3 `ELECTRON_RUN_AS_NODE`

DSH 宿主给子进程注入了 `ELECTRON_RUN_AS_NODE=1`，Electron 二进制看到它会退化成纯 node 模式，报 `Cannot find module 'electron'`。

**PowerShell 的 `Start-Process` 与 cmd 的 `set VAR=` 都清不掉它**，只有在 .NET `ProcessStartInfo` 层面 `Environment.Remove()` 才有效。

> 所以**必须走 `run.ps1`，不能双击 `electron.exe`**。

### 5.4 窗口透明与圆角

```
transparent: true
backgroundColor: '#00000000'
roundedCorners: false
hasShadow: false
```

**圆角必须由「窗口透明 + CSS 裁角」共同实现**。曾用 `transparent: false` + 实底 `backgroundColor`，结果窗口永远是**方角**。

**`hasShadow` 保持 `false`（别改回 `true`）**：Windows 对无边框透明窗基本不画原生阴影，而 CSS 的 `box-shadow` 只画在窗口矩形**内部**、且 `.win` 贴着四边，外阴影的可见部分全在窗口外 → 被直接裁掉。

配套方案：**窗口比内容大一圈 `SHADOW_PAD`** + CSS 用等量 padding 收回来。

> `SHADOW_PAD` 必须与 `renderer/skin.css` 的 `--shadow-pad` **完全一致**。

**`roundedCorners: false` 的理由**：透明窗下必须关掉原生圆角，否则原生裁角 + CSS 裁角两次裁切，半径叠加会让边缘发虚。

### 5.5 物理像素与逻辑像素的偏差

本机系统缩放 **113%**（窗口枚举实测 429×594 物理像素，而 BrowserWindow 逻辑尺寸是 380×560），但 renderer 里 `window.devicePixelRatio` **却报 1**。

**任何依赖 `devicePixelRatio` 的换算都会错 13%**。

解法：`physicalBounds()` 用 `getNativeWindowHandle()` 拿 HWND，再通过一个极小的 PowerShell 子进程调 `GetWindowRect` 读物理值。

### 5.6 孤儿防护已移除（务必不要加回来）

**原实现**：桥通过 `WHALE_PARENT_PID` 传宿主 pid，这里每 5 秒 `process.kill(PARENT_PID, 0)` 探测，宿主消失就自我了断。

**为什么删掉**：

1. **宿主一重启，所有还活着的小窗全部自杀**。而小窗是常驻组件，跨宿主重启存活恰恰是它该有的行为
2. **实测误杀**：宿主 PID 明明活着，小窗却在启动 5 秒后打出 `parent process gone, exiting`。原因是小窗拿到的 `WHALE_PARENT_PID` 是**上一个已退出宿主**的 pid
3. 现在入口是页面内小鲸鱼按钮，孤儿窗口有明确的用户出口

> **正确做法**：让**桥在卸载钩子里**主动关闭它自己拉起的窗口，而不是让子进程猜父进程的死活。

### 5.7 `run.ps1` 的写法约束

- **不要写 `$args`** —— `$args` 是 PowerShell 自动变量，赋值行为跨版本不一致
- `-Debug` **默认关闭**：debug 会给 `.win` 加一圈粉色描边，**顶掉阴影**

### 5.8 client 侧 JS 改动必须实地跑

`node --check` **只查语法**，查不出 TDZ。

**实际踩过**：`runSelfCheck()` 里 `cs.boxShadow` 写在 `const cs = getComputedStyle(elWin)` 之前 → 整个自检中断。

### 5.9 Windows 上做不到桌面毛玻璃

实测窗口内外条纹方差比 **0.935 ≈ 没模糊**。故**不做玻璃质感**，只保留透明换真圆角，内容区由 `.win` 自己铺不透明底色。

| 与悬浮条共用单实例锁 | 小窗开着时再拉起会静默退出。桥已做外部进程识别与复用 | 已缓解 |

## 七、文件与目录

```
whale-window/
├── main.cjs              Electron 主进程（窗口 / IPC / 状态持久化 / 崩溃自愈）
├── preload.cjs           受控通道 window.whale
├── run.ps1               启动脚本（必用）
├── package.json
├── assets/               图标资源
├── renderer/
│   ├── index.html        结构
│   ├── app.js            渲染逻辑 + SSE 接入
│   ├── skin.css          样式
│   └── crashed.html      崩溃兜底页
└── .userdata/            运行数据
```

**Electron 运行时**：共用仓库根 `runtime/electron.exe`（与小窗、悬浮窗共享，不各存一份副本）。

**主进程额外开关**：

| 开关 | 含义 |
|---|---|
| `--whale-no-restore` | **不读也不写**窗口状态记忆（验收脚本用） |
| `--whale-debug` | 开 DevTools + 高对比描边 |
| `--whale-width=` / `--whale-height=` | 显式尺寸，**优先级高于记忆值** |
