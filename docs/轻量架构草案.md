### 2.2 唯一通路原则

**第 1 层与第 3 层之间没有直接连线。** 两个 Electron 与页面按钮**都不 `require` 宿主模块**，只通过 `127.0.0.1:19387` 的 HTTP 说话。

这条原则的收益：
- 宿主可随时重启，桥不可用则三个客户端进入**断连态而非崩溃**（R-1/R-5）；
- 三个客户端可独立开发、独立调试（不需要宿主源码）；
- 接口即契约，22 条路由就是完整的耦合面。

## 三、核心模块

### 3.1 桥（whale-bridge）

| 模块 | 职责 | 输入 | 输出 | 纯函数 |
|---|---|---|---|---|
| `host.js` | 插件生命周期：注册服务、装路由、卸载清理 | ctx | — | 否 |
| `host-impl.js` | HTTP 服务 + 22 路由分发 + 订阅宿主事件 | ctx / HTTP 请求 | HTTP 响应 | 否 |
| `fold.mjs` | 双折叠器：hudBySession（全量聚合）/ sessionFold（保留 40 条） | 事件流 | 折叠态 | **是** |
| `usage-stats.mjs` | token 口径：四桶求和、pressure 计算、速度窗口 | usage 对象 / 时间戳 | 统计结果 | **是** |
| `zstd-frame.mjs` | 逐帧 zstd 解码（扫魔数 → 切片 → 解压 → 拼接） | Buffer | Buffer | **是** |
| `client.js` | 页面内小鲸鱼按钮 | DOM 事件 | HTTP 调用 | 否 |

**为什么折叠器与统计内核要独立成纯函数模块**：它们是最容易出错的逻辑（seq 去重、窗口过期、四桶口径），必须是**可脱离宿主单测**的。桥 PRD F4 也明确要求「服务不可用时按同样规则在本地折叠」，所以同一份纯函数要能被复用。

### 3.2 悬浮条（whale-hud）

| 模块 | 职责 |
|---|---|
| `main.cjs` 窗口管理 | 创建无边框透明窗口，顶边对齐，P1/P2/P3 三种形态切换 |
| `main.cjs` 几何计算 | **物理像素走 HWND + `GetWindowRect`**，不用 `devicePixelRatio` |
| `main.cjs` 状态机 | 展开 / 收起 / 球形态；悬停进入 P3 |
| `renderer/hud.js` | SSE 接入 `/whale/hud/events`，渲染五元素 |
| `renderer/hud.js` 滚筒 | 多会话轮播（F4） |
| `lib/usage-stats.mjs` | 与桥同源的统计内核（渲染侧兜底） |

**关键设计**：悬浮条**不自己算 token**，只渲染桥给的数。`lib/usage-stats.mjs` 的存在是为了「桥不可用时不显示假数」——它算出来的值只用于**校验**桥的数据是否自洽，不用于替代。这符合降级原则「宁可显示 `–` 不显示错的数」。

### 3.3 小窗（whale-window）

| 模块 | 职责 |
|---|---|
| `main.cjs` 窗口管理 | 无边框窗口、圆角、置顶、关闭语义（F10） |
| `main.cjs` 状态记忆 | 窗口位置/尺寸持久化（F12） |
| `main.cjs` 崩溃自愈 | 渲染进程崩溃 → 重载；连续失败 → 兜底页（F11/F13） |
| `renderer/app.js` | SSE 接入 `/whale/events`、消息流渲染、任务坞、命令面板 |
| `renderer/app.js` 输入区 | 提交走 `POST /whale/send`；斜杠命令走 `POST /whale/command` |

**崩溃自愈的状态机**（F11/F13）：

```
运行 ──render-process-gone──→ 计数+1
                                │
                   计数 ≤ 2 ────┴──── 计数 > 2
                     │                    │
                  reload()            加载 crashed.html
                     │                    │
                  成功 → 计数清零      提供"重新加载"按钮
```

### 3.4 按钮（whale-button）

宿主客户端插件，注入 DSH 页面右下角。点击 → `POST /whale/open` 拉起小窗。

**归属决策**（见 §5.4）：按钮代码物理上放 `whale-bridge/lib/client.js`（因为 Cordis 插件的客户端半侧必须与宿主插件同包声明），`whale-button/` 目录保留为**文档与产物位置**，不重复实现。

## 四、数据模型

### 4.1 桥对外的数据形状

**`GET /whale/hud`**（悬浮条全量快照）：

```ts
interface HudSnapshot {
  bridge: { version: string; port: number; uptimeMs: number };
  sessions: Array<{
    sessionId: string;
    title: string;
    workspace: string;
    speed: {
      phase: 'running' | 'idle' | 'unknown';
      tokPerSec: number | null;
      frozen: boolean;
    };
    contextUsed: number | null;
    contextWindow: number | null;
    totalOutput: number;
    totalInput: number;
    totalCacheRead: number;
    steps: number;
    turns: number;
    lastUsageAt: number | null;
  }>;
  activeSessionId: string | null;
}
```

**`GET /whale/events`**（SSE，事件信封）：

```
id: <seq>
event: <eventType>
data: {"seq":N,"time":<epochMs>,"type":"...","data":{...}}

```

**`GET /whale/panel?sessionId=`**（小窗面板数据）：

```ts
interface PanelData {
  sessionId: string;
  messages: Array<{ role: 'user'|'assistant'|'tool'; text: string; seq: number }>;
  todos: Array<{ content: string; status: 'pending'|'in_progress'|'completed' }>;
  permissionPreset: string | null;
  model: { provider: string; model: string } | null;
}
```

### 4.2 内部折叠态

```ts
// hudBySession：不设 tail，保留全部 usage 聚合
interface HudFold {
  sessionId: string;
  lastSeq: number;              // 水位，按 seq 去重
  totalInput: number;
  totalOutput: number;
  totalCacheRead: number;
  steps: number;
  turns: number;
  lastUsageAt: number | null;
  samples: Array<{ at: number; outputTokens: number }>;  // 8 秒窗口
  phase: 'running' | 'idle' | 'unknown';
}

// sessionFold：保留最近 40 条渲染事件
interface SessionFold {
  sessionId: string;
  lastSeq: number;
  tail: RenderEvent[];          // 上限 40
}

type RenderEvent =
  | { kind: 'user'; text: string; seq: number }
  | { kind: 'assistant'; text: string; seq: number }
  | { kind: 'tool'; name: string; state: 'running'|'done'|'error'; seq: number }
  | { kind: 'todo'; todos: Todo[]; seq: number };
```

### 4.3 token 口径（D1 方案 C 落地）

| 输出 | 计算 | 来源 |
|---|---|---|
| `contextUsed` | `pressureFrom(usage) = inputTokens + (cacheReadTokens ?? 0) + (cacheWriteTokens ?? 0)` | 末条 `assistant/message.data.usage` |
| `contextWindow` | 同名 | `request/context.data.contextWindow` |
| `totalInput` | Σ `inputTokens` | 全部 `assistant/message.data.usage` |
| `totalOutput` | Σ `outputTokens` | 同上 |
| `totalCacheRead` | Σ `cacheReadTokens` | 同上 |

**实测约束（K-10）**：落盘 `usage` 对象只有 4 个字段（`inputTokens` / `outputTokens` / `totalTokens` / `cacheReadTokens`），**没有 `cacheWriteTokens`**。故该项恒为 0 兜底，**不得虚构**。`totalTokens` 含缓存读，**不能当上下文占用**。

**取值优先级**：宿主 `session-projection` 服务的 `tokenUsage` / `contextPressure` 投影 → 不可用时桥本地折叠。

### 4.4 速度算法（F5）

```
SPEED_WINDOW_MS = 8000
HEARTBEAT_MS    = 2000

采样：每次 usage 到达 → samples.push({at: now, outputTokens})
计算：speed = (窗口内 outputTokens 之和) / (窗口时长秒)
归零：窗口内样本全过期 → tokPerSec = 0（累计数字不动）
冻结：回合结束 → frozen = true
清空：新回合开始 → samples = []
```

## 五、服务端逻辑（桥）

### 5.1 生命周期

```
apply(ctx):
  1. 读配置（端口 19387，固定）
  2. 创建折叠器实例（hudBySession / sessionFold）
  3. 订阅 ctx.on('session/event', onSessionEvent)
  4. 订阅 agent/status（维护 phase）
  5. 启动 HTTP 服务，listen('127.0.0.1', 19387)
     └ 失败（EADDRINUSE）→ 明确落日志，不静默换端口
  6. 启动 2 秒心跳（重算速度 + 推 SSE 心跳）

dispose():
  1. 关闭自己拉起的小窗进程
  2. 关闭 HTTP 服务（避免端口泄漏）
  3. 退订事件
```

### 5.2 请求处理链

```
HTTP 请求
  → 路由匹配（22 条）
  → 是否 SSE？（/whale/events、/whale/hud/events）
      ├ 是 → 注册客户端到广播表 → 写 Last-Event-ID 之后的事件
      └ 否 → 业务处理 → JSON 响应
```

### 5.3 事件处理链（实时性关键路径）

```
宿主 append 事件
  → ctx 'session/event' 回调（进程内，零延迟）
  → 分发到两个折叠器
      ├ hudBySession.onEvent()  → 更新聚合 → 广播到 /whale/hud/events
      └ sessionFold.onEvent()   → 更新 tail → 广播到 /whale/events
  → SSE 立即写入（不等心跳）
```

**P-5 达标依据**：这条链上没有轮询、没有文件 IO、没有跨进程跳转。唯一开销是折叠计算（纯内存加法）。

### 5.4 归属决策：按钮代码放哪

**问题**：`whale-button/` 是独立目录，但 Cordis 的客户端半侧插件必须与宿主插件**同包声明**（`client.js` 要在 `package.json` 里声明为客户端入口）。

**决策**：按钮代码物理上放 `whale-bridge/lib/client.js`；`whale-button/` 目录**不重复实现**，只放：
- 一份说明（指向 `whale-bridge/lib/client.js`）；
- 验收截图等产物。

**理由**：避免同一份代码两处维护（单一事实源原则）。代价是目录名与实际位置不完全对应，**故在此显式记录**。

### 5.5 进程管理（F6）

```
POST /whale/open:
  → 查已拉起窗口表
      ├ 存活 → 返回 {pid, reused: true}
      └ 不存在/已死 → spawn:
           env: delete ELECTRON_RUN_AS_NODE     ← 必须
           args: ['--no-sandbox', 'main.cjs']
           exe:  <仓库根>/runtime/electron.exe
           cwd:  <仓库根>/whale-window
         → 记录 pid → 返回 {pid, reused: false}

POST /whale/close:
  → 按 pid 关闭（只关自己拉起的）

不做孤儿防护（F6 明确）：
  ✗ 不加 WHALE_PARENT_PID 探测
  ✗ 不让子进程猜父进程死活
```

## 六、错误处理与降级

| 场景 | 表现 | 依据 |
|---|---|---|
| 桥连不上 | 三个客户端显示断连态，不崩溃 | R-1 / R-5 |
| SSE 断开 | 1s→15s 退避重连，带 `Last-Event-ID` 续传 | R-3 / F-5 |
| token 数据缺失 | 显示 `–`，不显示 0 或猜测值 | 降级原则 |
| 端口占用 | 桥启动失败 + 明确日志，不静默换端口 | C-8 / F-7 |
| 渲染进程崩溃 | ≤2 次重载；>2 次进兜底页 | F11 / F13 |
| 宿主事件类型未知 | 跳过并计数，不中断 SSE | R-5 |
| 落盘解码失败 | 回退纯 JS 解码器；再失败报错 | K-12 |
