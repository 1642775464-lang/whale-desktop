# 步骤 7 · 规整项目文档

## 概述

把散落在 `docs/` 里的十份规划文档收拢成**根目录三件套**，确立冲突裁决规则，并清理掉已被否决的绕路产物。

## 三件套结构

| 文件 | 层级 | 作用 |
|---|---|---|
| Whale-PRD.md | 需求层入口 | 指向三份产品 PRD，收拢共同硬约束与 v2 变更 |
| Whale-ARCHITECTURE.md | 架构层入口 | 指向边界/技术栈/架构/设计规范，确立四条架构铁律 |
| Whale-STATUS.md | 状态层 | 反映实测现状，不写声明 |

## 冲突裁决

PRD > ARCHITECTURE > STATUS

## 为什么拆三份 PRD

三个产品的界面形态、运行方式、用户操作完全不同。合在一起会让「逐功能可测」的验收表彼此污染；拆开后每份 PRD 的功能列表、用户流程、页面清单、验收编号互不干扰。

## 架构铁律（可机械检查）

| 编号 | 铁律 | 检查方式 |
|---|---|---|
| A-1 | 呈现层不得 require 宿主包 | tests/layering.test.mjs 静态扫描 |
| A-2 | 唯一通路 127.0.0.1:19387 | 扫描硬编码宿主端口 |
| A-3 | 纯函数模块不引 IO 依赖 | 单测脱离宿主运行 |
| A-4 | 渲染层零框架零构建 | 目录内无 package.json 依赖 |
