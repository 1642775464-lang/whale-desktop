## SSE：一半的正确性在协议层

响应头是不是 `text/event-stream`、帧格式对不对、断开后服务端有没有摘掉。这些用单元测试测不到，只有真的发起连接才看得见。所以本片专门写了端到端冒烟测试，用 `fetch` 的流式响应读真实帧。

```flow
宿主 append 事件
→ 事件管线分发
→ 立即广播到两个频道（不等心跳）
→ 客户端 1 秒内收到帧（实测计时断言）
```

**为什么事件到达不等心跳**：心跳只负责重算速度。速度是「时间的函数」——没有新事件时它也得动；而事件本身必须一到就推，等心跳会把实时性拖成 2 秒级。

### Last-Event-ID：续传比想象中容易测错

断线重连要补回漏掉的帧。这里踩了两个坑：

```kv
手搓折叠态: 冒烟测试里手写的 fold 对象漏了 totals 字段，折叠视图直接 TypeError。改用折叠器自己的 ensureSession 造会话——手搓对象会假装自己懂内部结构
重连首帧: 服务端一连上就先写 `: connected` 注释帧，回补帧在**第二帧**。只读一帧会误判成「没有续传」
```

## 四个决策的落地

| 编号 | 决策 | 怎么落的 |
|---|---|---|
| S3-D1 | send 的运行中行为 | 空闲 → `followup`；运行中默认 `followup`（排队到下一回合）；显式 `mode:"steer"` 走 `steer`，非运行态拒掉并返回 409 |
| S3-D2 | approval 应答机制 | **瀑布拦截**，不是查询+应答。先 `next()` 把决定权交出去，只在无人应答时补答案 |
| S3-D3 | models 数据源 | 探测不到就返回空数组 + 明确 `reason`，**不硬编码模型名** |
| S3-D4 | 心跳载荷 | 只推随时间变化的三个数（速度 / 占用 / 窗口），全量快照仍走 `/whale/hud` |

**S3-D2 为什么必须是「无人应答时才接管」**：宿主主界面自己能弹确认框，那是用户最习惯的入口。若桥先答，用户会发现自己点的按钮没反应——因为他根本看不到那个框，桥已经替他答了。所以桥只做「宿主 UI 不在场时」的备用通道，超时上限 30 秒，宁可答不上也不挂住宿主回合。

## 闸门 7：把纪律变成代码

这一片新增了一道闸门，它不是检查产品代码的。

```kv
强制 28: 回复正文禁止出现内部摘要类内容（analysis / summary / 复盘 / 「我读了X我改了Y」式流水）
强制 29: 闸门 7 是它的执行者 —— tools/check-reply.mjs --selftest
理由: 空壳规则比没有规则更危险，它会让人以为纪律被执行了
```

`--selftest` 用**正样例（必须被拦）+ 反样例（必须放行）**双向证明规则没退化。写它的过程中正则本身错了两次：`\s*` 会吃掉换行导致整块文本被当成一行；`\b` 在中文后失效（JS 的 `\w` 只含 ASCII）。这两次都是自检抓住的——**规则自己也需要被测试**。
