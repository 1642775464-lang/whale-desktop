写图标时我凭印象编了一段鲸鱼 path，还在注释里声称「与源文件同一形状」。 实际上它跟真图标完全不是一条鲸鱼。

而 PRD 早就警告过这件事：

那条 path 有 3394 个字符，人抄必错。项目里本来就有 tools/whale-icon.mjs 处理悬浮条的同类问题，我照它的做法补了 tools/whale-btn-icon.mjs：

3394 字符逐字符一致

为什么要「独立复核」，而不是听工具自己报：--check 用的是它自己的抽取函数， 万一两边错得一致（比如正则同时匹配到别的东西），自校验会一致地通过。

依赖扫描：不是放宽，是换把更严的尺子

按钮是浏览器文件，它 require("react") —— 但 React 来自宿主的模块表，不是 npm 依赖。

依赖扫描当场拦下了它。我没有「把 client.js 加进忽略名单」——那会留个洞 （将来往客户端里 import fs 也没人拦）。改成按 exports["./client"] 识别浏览器侧文件， 然后给它一把更严的尺子：

宿主侧
只允许 node: 内置与相对路径
浏览器侧
允许宿主模块表模块（react 等），但禁止 node: 内置模块

第二行是收紧：浏览器里根本没有 fs，引了必崩，现在会被拦住。
