# 日用阶段修掉的四个缺陷

## 一句话

插件装进真宿主开始日用后，你陆续报出 **4 个缺陷**。四个都修了，四个都过了你的逐项验收。

值得单独记一页的原因是：**这四个没有一个是测试发现的** —— 假环境对它们全都无效。

```kv
缺陷来源: 用户日常使用中发现
测试状态: 520 个全绿（修之前也是全绿的）
共性: 要么跨进程，要么依赖宿主的真实数据结构
```

## 四个缺陷

| # | 现象 | 真因 |
|---|---|---|
| 1 | 点悬浮条鲸鱼收不起小窗 | PRD F2① 是**切换**语义，实现函数名叫 toggle、里面只调了 open |
| 2 | 右下角图标「就是个透明的」 | 源 svg 是 `fill="none"`，颜色本由悬浮条的 CSS 补；客户端插件没有样式表 |
| 3 | 点鲸鱼无反应、绿环不灭 | `target` 被 HTTP 处理器静默丢掉 → 返回「成功」但一个都没关 |
| 4 | token 流速与上下文不上下居中 | 基线对齐的行盒贴顶，36px 盒子里少掉的 5.6px 全跑到下面 |

## 第 3 个最该记

它暴露的是一种**比报错更难查**的失败：

```sequence
悬浮条->桥: POST /whale/close {target:"window"}
桥-->悬浮条: 200 {"ok":true,"closed":0}
悬浮条->悬浮条: 拿到 ok，更新绿环
用户->用户: 看着「点了没反应」
```

桥返回了成功，悬浮条也诚实地按成功处理了 —— **但一个窗口都没关**。

真因是我泛化桥时只在底层 `windows.close` 里实现了按 `target` 关，
**忘了在 HTTP 处理器里把这个参数传下去**。参数丢了以后，代码落到「按 pid 匹配」分支，
匹配不到任何窗口，于是 `closed: 0`。

我在你的真桥上做了 A/B 复现：

```annot # 真桥 A/B 对照
开小窗 → pid [18748]{注释}
发 {"target":"window"} → [200 {"ok":true,"closed":0}]{!窗口还在：参数被丢掉}
对照 {"all":true} → [200 {"ok":true,"closed":1}]{窗口关掉了：close 本身没坏}
```

最后一行是关键对照：**它证明 close 本身没坏，坏的只是参数没传下去**。

## 三次「我以为」，三次被证据纠正

这一段比修 bug 本身值钱。

```annot # 以为 vs 实际
我以为「图标透明」是 [CSS 没生效]{!实际：探针实测 fill 已是 rgb(31,36,48)、::after 正常}
```

**证据把方向拨正了**：渲染层没问题，问题在桥的处理器。没有这一步，我会去改一堆
本来没坏的 CSS。

**第二次**：我以为「绿环没灭」是你没重启。查了进程启动时间（18:26:12）与我的提交时间
（18:21:35）—— **进程比修复新**，跑的就是新代码。所以是真 bug。

**第三次**：我以为「标题没渲染」是界面问题。查桥的返回：`title = ''`。
**桥根本没拿到标题**，界面无过。

三次都靠**先取证再改代码**，避免了改错地方。

## 为什么写量测探针，而不是目测改

第 4 个缺陷是「看着不居中」。这四个字至少有三种成因：

```tree list
看着不居中
  盒子没居中
    修法：改父容器的 align-items
  盒子居中了，但内部行高把字顶偏
    修法：改行盒高度（本次就是这种）
  基线与汉字字形中心不一致
    修法：加补偿或用 flex 居中
```

三者修法完全不同，估着改只能反复试错。所以我写了个量测探针，
量每个元素的**文字视觉中心**与条中心的偏差：

```limits
居中偏差（修前） | 6 / 6 | px
居中偏差（修后） | 0 / 6 | px
```

实测偏 **6px**，而 `(36 − 24.75) / 2 ≈ 5.6px` —— 数字与算式对上了，
一次就改对。修完偏差 0。

## 一条自我纠正

我给第 4 个缺陷写的第一版契约断言是**空壳**：

它只检查「`closeSmallWindow` 和 `openSmallWindow` 这两个名字有没有出现过」。
我把代码改回错的样子做注入验证时，**它照样全绿** —— 因为方法名还留在文件里，
只是调用关系变了。

改成检查**真实的条件分支结构**后再注入，立刻变红。

> **凡是没做过注入验证的断言，都不能算防线。**

## 新增的验收工具

```kv
hud-toggle-probe: 进真窗口实测图标填充与绿环 ::after，派发真鼠标序列点鲸鱼
hud-align-probe: 量每个元素的文字视觉中心与条中心偏差（容差 ±1.5px）
verify-btn-icon: 另写一套抽取逻辑复核图标，不依赖工具自己的比对
bridge-preflight: 补标题通路：灌一条不含标题的事件，验两条接口能否从投影补出来
```

第二个「另写一套逻辑」是**故意**的：`--check` 走工具自己的抽取函数。
万一两边错得一致（比如正则同时匹配到别的东西），自校验就会一致地放行。
