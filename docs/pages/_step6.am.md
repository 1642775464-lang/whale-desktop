# 第六步 · 轻量架构草案

## 结论

架构分**三层**：呈现层（悬浮条 / 小窗 / 按钮）、桥（Cordis 插件）、宿主（既有不改）。

**唯一通路原则**：呈现层与宿主之间**没有直接连线**，只走 `127.0.0.1:19387` 的 HTTP/SSE。三个客户端都不 require 宿主包。

## 目录分层

| 目录 | 层 | 内容 |
| --- | --- | --- |
| `runtime/` | 运行时 | 三件套共享 electron.exe |
| `whale-bridge/` | 桥 | 插件入口 + 22 路由 + 折叠器 + 纯函数 |
| `whale-hud/` | 呈现 | 悬浮条（主进程 / 渲染 / 统计内核） |
| `whale-window/` | 呈现 | 小窗（主进程 / 渲染 / 兜底页） |
| `whale-button/` | 呈现 | 页面内按钮 |
| `tests/` `tools/` | 工程 | 测试与六闸门脚本 |

## 核心模块

| 模块 | 职责 | 纯函数 |
| --- | --- | --- |
| `fold.mjs` | 双折叠器（全量聚合 / 保留40条） | 是 |
| `usage-stats.mjs` | token 口径 + 速度窗口 | 是 |
| `zstd-frame.mjs` | 逐帧 zstd 解码 | 是 |
| `host-impl.js` | HTTP 服务 + 路由 + 订阅 | 否 |
| `main.cjs` ×2 | 窗口管理 / 状态机 / 崩溃自愈 | 否 |

折叠器与统计内核**独立成纯函数**，因为它们是出错最多的地方，必须能脱离宿主单测。

## 数据模型

| 输出 | 计算 |
| --- | --- |
| 上下文占用 | `inputTokens + cacheRead + cacheWrite` |
| 累计输入 | Σ `inputTokens` |
| 累计输出 | Σ `outputTokens` |
| 累计缓存读 | Σ `cacheReadTokens` |

实测约束：落盘 usage **没有 cacheWriteTokens**，该项恒为 0 兜底，**不得虚构**。`totalTokens` 含缓存读，不能当上下文占用。

## 关键路径（实时性）

宿主事件 → 进程内回调 → 双折叠器 → SSE 立即写

这条链上**没有轮询、没有文件 IO、没有跨进程跳转**，是 P-5（≤300ms）的达标依据。
