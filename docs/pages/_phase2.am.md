# 二期清单

## 一句话

**二期范围从来没有汇总过。** PRD、待决清单、各片范围声明里散着十几条「延后」，
但没人把它们列成一张表。这一页就是那张表。

```kv
来源: docs/待决清单.md 第三节 + 三份 PRD 的「已知限制」+ 各片范围声明
性质: 全部是**已记录的刻意降级**，不是漏做
本页做法: 只汇总与分类，不含新决策
```

## 先说清一件事：这些不是缺陷

每一处降级都在文档里写明了**为什么**，且大多配了降级行为。
比如 `＋ 添加` 按钮**存在**（`index.html` 的 `btnAdd`），只是点了不产生副作用 ——
这正是待决清单写的「面板列出但不产生副作用」。

```callout info 判断口径
文档里写明「延后 / 二期 / 能力未接通」的 = 二期范围。
文档里没写、实际又缺的 = 缺陷，那要单独修，不进这张表。
```

## 一、按性质分四类

```tree list
二期候选
  能力补齐类（宿主有服务，桥没接）
    ⚙ 侧边工作台
    ＋ 添加（上传文件/文件夹/云盘）
    按需确认（☰ 菜单项）
    部分灰项面板
  体验优化类（能用，但不够好）
    历史会话唤醒提速（v2 直读落盘）
    顶栏工作区色块显示真名
  技术做不到类（不是"没做"，是"做不到"）
    桌面毛玻璃
    全局热键
  待定类（需求没定）
    语音输入 / 通话 / 麦克风 / 共享
```

## 二、逐项清单

| 项 | 现状 | 为什么没做 | 可行性 |
|---|---|---|---|
| `⚙` 侧边工作台 | 点击提示「能力未接通」 | 原型未定义具体内容 | 中：需先定内容 |
| `＋` 添加（上传/文件夹/云盘） | 按钮在，点了无副作用 | 明确列为二期 | 中：桥需接 attachments |
| `☰ → 按需确认` | 灰角标，点击无静默效果 | 能力未接通 | 中：桥已有 approval 通路 |
| 顶栏工作区色块 | 固定渐变小圆点 | 无真实数据源 | 低：读会话 header 的 cwd |
| **历史会话唤醒提速** | 约 20 秒（宿主行为） | 不可控 | **高：v2 改为桥直读落盘** |
| 语音输入 / 通话 / 麦克风 / 共享 | 刻意置灰（外观对齐豆包） | 能力二期补 | 低：宿主有 speech-to-text 插件 |
| 桌面毛玻璃 | 阴影 + 描边代替 | Windows 上跨不了合成层（实测方差比 0.935） | **做不到** |
| 全局热键 | 无 | DSH 壳内 0 处 `globalShortcut`，需第三方库 | 低：违反零依赖 |

## 三、最值得先做的一条

```callout ok 历史会话唤醒提速
```

现在切到历史会话要等约 **20 秒**——因为桥只能先「唤醒」它才能读数据。
待决清单早就写了 v2 的方案：**桥直读落盘，读不依赖唤醒**。

我核实过：宿主的 `dsh-api-session-controller` 确实有读持久化的能力
（`ensureSession` / persisted header 相关方法），所以这条路**技术可行**。

这是唯一一条「现状明显影响日用、且有明确低成本方案」的项。

## 四、几处需要你先定的

这几项我做不了主 —— 按纪律，需求上的缺口该你定：

```kv
侧边工作台做什么: 原型只说"工作台"，没定义内容。展示元信息？还是编辑能力？
语音输入要不要: 宿主有 speech-to-text 插件可接，但要不要接是你的产品决策
＋ 添加的范围: 上传到哪、走哪条通路，需要定
二期怎么切: 一片做完 vs 分多片（现在的项目是六片制）
```

## 五、我的建议

```timeline
第一步 | 只做唤醒提速 | 影响日用最直接、方案已定、成本最低，可独立成一片
第二步 | 能力补齐三件 | 侧边工作台 / ＋添加 / 按需确认，各需先定内容
第三步 | 语音 | 需你先定要不要
最后 | 毛玻璃与全局热键 | 建议明确"不做"，写进文档打消念头
```

**第一步为什么不打包**：唤醒提速有明确判据（20 秒 → 多少），
而其余几项都卡在「内容没定」。混在一起会变成一片做不完的大切片，
违背小步迭代的原则。
