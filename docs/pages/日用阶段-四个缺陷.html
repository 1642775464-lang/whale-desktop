第 3 个最该记

它暴露的是一种比报错更难查的失败：

桥返回了成功，悬浮条也诚实地按成功处理了 —— 但一个窗口都没关。

真因是我泛化桥时只在底层 windows.close 里实现了按 target 关， 忘了在 HTTP 处理器里把这个参数传下去。参数丢了以后，代码落到「按 pid 匹配」分支， 匹配不到任何窗口，于是 closed: 0。

我在你的真桥上做了 A/B 复现：

开小窗 → pid 18748注释
发 {"target":"window"} → 200 {"ok":true,"closed":0}窗口还在：参数被丢掉
对照 {"all":true} → 200 {"ok":true,"closed":1}窗口关掉了：close 本身没坏

最后一行是关键对照：它证明 close 本身没坏，坏的只是参数没传下去。

为什么写量测探针，而不是目测改

第 4 个缺陷是「看着不居中」。这四个字至少有三种成因：

看着不居中
  • 盒子没居中
    • 修法：改父容器的 align-items
  • 盒子居中了，但内部行高把字顶偏
    • 修法：改行盒高度（本次就是这种）
  • 基线与汉字字形中心不一致
    • 修法：加补偿或用 flex 居中

三者修法完全不同，估着改只能反复试错。所以我写了个量测探针， 量每个元素的文字视觉中心与条中心的偏差：

居中偏差（修前）6 / max 6 px
0246810
居中偏差（修后）0 / max 6 px
0246810

实测偏 6px，而 (36 − 24.75) / 2 ≈ 5.6px —— 数字与算式对上了， 一次就改对。修完偏差 0。
