## 装配链路

```flow LR
按钮[页面右下角鲸鱼] -->|POST /whale/open| 桥[127.0.0.1:19387]
桥 -->|spawn| HUD[悬浮条进程]
```

按钮**只走 HTTP**，不自己起进程——拉起窗口是桥的职责（铁律 A-2）。
桥有进程表、能复用、能防重；按钮自己 spawn 会绕过那条唯一通路。

## 一个超出范围、但躲不掉的改动

写按钮时才发现：**桥原来完全不管悬浮条进程**——`windows.mjs` 是小窗专用的，入口写死。

按钮要「同时拉起两个」，桥就必须能拉悬浮条。这超出我范围声明里写的「不改桥路由」，
所以我先列了影响清单请你确认，你点头后才动。

```kv
改动: windows.mjs 泛化出 TARGETS 表 + /whale/open 加可选 target 参数
不破坏: 缺省仍是 window，既有小窗行为不变（windows 单测 17 个全过）
关键修复: 复用改为**按目标分开**
```

最后那条是泛化时才显现的坑：原先是「任意窗口存活就复用」。
泛化后如果照搬，**存活的悬浮条会挡住拉起小窗**，表现就是「点按钮只起来一个」。

## 我犯的一个错，和它引出的防线

写图标时我**凭印象编了一段鲸鱼 path**，还在注释里声称「与源文件同一形状」。
实际上它跟真图标完全不是一条鲸鱼。

而 PRD 早就警告过这件事：

```callout warn PRD 原文：不要试图手抄或用 edit 替换整串，会抄错
```

那条 path 有 **3394 个字符**，人抄必错。项目里本来就有 `tools/whale-icon.mjs`
处理悬浮条的同类问题，我照它的做法补了 `tools/whale-btn-icon.mjs`：

```kv
注入: 从 favicon-whale.svg 机械抽取，写进 client.js 的标记块之间
校验: --check 模式比对注入结果与源文件
独立复核: verify-btn-icon.mjs 另写一套抽取逻辑再比一次
实测: 3394 字符逐字符一致
```

**为什么要「独立复核」，而不是听工具自己报**：`--check` 用的是它自己的抽取函数，
万一两边错得一致（比如正则同时匹配到别的东西），自校验会一致地通过。

## 依赖扫描：不是放宽，是换把更严的尺子

按钮是浏览器文件，它 `require("react")` —— 但 React 来自宿主的模块表，不是 npm 依赖。

依赖扫描当场拦下了它。我没有「把 client.js 加进忽略名单」——那会留个洞
（将来往客户端里 `import fs` 也没人拦）。改成按 `exports["./client"]` 识别浏览器侧文件，
然后给它一把**更严**的尺子：

```kv
宿主侧: 只允许 node: 内置与相对路径
浏览器侧: 允许宿主模块表模块（react 等），但**禁止 node: 内置模块**
```

第二行是收紧：浏览器里根本没有 `fs`，引了必崩，现在会被拦住。
