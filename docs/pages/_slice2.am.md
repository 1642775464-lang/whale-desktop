# 切片 2 完成：事件订阅与折叠器内核

## 这一片做了什么事

把宿主的**事件流**接进桥。切片 1 交付的是「服务能起来、路由能应答」，但服务手里是空的；这一片让它真正**收到宿主正在发生的事**，并折成两种可读状态。

一句话验收：往假 ctx 里推一条 `assistant/message`，能从 `http://127.0.0.1:19387/whale/fold` 把它读回来。

```flow
宿主 append 事件
→ ctx 触发 session/event 回调
→ 事件管线分发（进程内，零跳转）
→ 双折叠器各自吸收
→ HTTP 立即可读
```

## 三个纯函数内核

这三个模块不读时钟、不读文件、不碰网络，因此可以脱离宿主单测——这是它们能先把逻辑钉死的原因。

```kv
zstd-frame.mjs: 逐帧解 zstd。宿主日志里有数百个独立帧，整包解压只出第一帧，必须扫魔数 28 b5 2f fd 切片后逐帧解再拼接
usage-stats.mjs: token 口径与速度采样。上下文占用 = inputTokens + cacheReadTokens + cacheWriteTokens；累计量取四桶求和
fold.mjs: 双折叠器。悬浮条只累计量（不设 tail），小窗只留最近 40 条（设 tail）
```

**为什么折叠器要拆成两个，而不是一个**：两者用途相反。悬浮条要的累计数字一旦设了 tail 就会被裁掉历史；小窗要的消息流一旦全量存就会随会话无限增长。合并成一个，两种需求会互相牵制。

## 口径与降级

```callout
取不到就给 null，不给 0
```

界面上「0」和「没有值」是两回事。`usage` 无效时 `pressureFrom` 返回 `null` 而非 0，渲染层据此显示 `–`。这是《边界与 NFR 说明书》里「宁可显示 – 不显示错的数」的落地。

```kv
未知事件类型: 跳过并计数，绝不抛错。宿主有约 60 种已注册类型且还会增加，折叠器不认识某类型是正常情况，不是错误
回调异常: 全部包 try，只累加 callbackErrors 并落日志，不把异常抛回宿主管线
落盘解码失败: readSessionLog 返回 {ok:false, reason}，不抛错，由调用方决定降级
```
