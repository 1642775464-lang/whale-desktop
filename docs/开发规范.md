## 二、第一层 · 代码风格

### 2.1 命名（强制）

| 对象 | 规则 | 例 |
|---|---|---|
| 文件（可执行/模块） | `kebab-case` 或架构已定名 | `host-impl.js`、`usage-stats.mjs` |
| 纯函数模块 | `.mjs` 后缀 | `fold.mjs` |
| 主进程/预加载 | `.cjs` 后缀 | `main.cjs`、`preload.cjs` |
| 常量 | `SCREAMING_SNAKE_CASE` | `SPEED_WINDOW_MS`、`PORT` |
| 函数/变量 | `camelCase` | `pressureFrom`、`hudBySession` |
| 类 | `PascalCase` | `BridgeServer` |
| 布尔量 | `is/has/can/should` 前缀 | `isRunning`、`hasPending` |

**强制 1**：不得使用拼音命名。
**强制 2**：不得使用无意义缩写（`tmp`、`data1`、`obj2`）。业界通用缩写（`ctx`、`req`、`res`、`id`）例外。

### 2.2 注释与语言（强制）

- **强制 3**：代码内注释用**中文**；标识符用英文。
- **强制 4**：每个文件顶部必须有文件头注释，说明**职责**与**所属层**：

```js
// whale-bridge/lib/fold.mjs
// 职责：双折叠器 —— hudBySession 全量聚合 / sessionFold 保留 40 条
// 层级：纯函数（仅依赖 Node 内置，不引宿主 API）
```

- **强制 5**：注释解释**为什么**，不解释**是什么**。`i++ // 自增` 属违规。
- **强制 6**：凡与宿主行为对齐的代码，注释须标出宿主侧对应位置（文件:行），便于日后核对：

```js
// 对齐宿主 dsh-api-session-controller/lib/index.js:994-1000
agent.cancel({ kind: "user" }, { keepInbox: true });
```

### 2.3 格式（强制）

- **强制 7**：缩进 2 空格，不使用 Tab。
- **强制 8**：行尾 LF，**不使用 CRLF**（`.gitattributes` 钉死，见步骤 9）。
- **强制 9**：语句结尾必须有分号。
- **强制 10**：字符串统一用双引号。
- **强制 11**：单行不超过 120 字符。
- **强制 12**：文件末尾保留一个空行，无多余空行。

## 三、第二层 · 工程规范

### 3.1 模块拆分（强制 —— 用户明确要求）

> **用户原话：代码应该根据架构按模块拆分，确保后期可维护。**

这是本规范**最重要的一条**。拆分依据不是个人喜好，而是架构草案已定下的**分层边界**。

#### 3.1.1 三条拆分规则

**强制 13 · 单一职责**：一个文件只承担一个明确职责。判定标准——**能否用一句不含「和」的话说清它做什么**。

- ✅ `usage-stats.mjs` —— 「计算 token 统计」
- ❌ `main.cjs` —— 「管窗口**和**几何**和**状态机」

**强制 14 · 文件规模上限 500 行**（用户拍板）：

| 类型 | 上限 | 超出时 |
|---|---|---|
| 所有 `.js` / `.mjs` / `.cjs` | **500 行** | 必须拆分为多个模块 |
| 纯函数模块（`fold.mjs` 等） | **300 行** | 同上 |

纯函数模块更严，因为它们逻辑密度高且必须能脱离宿主单测；超过 300 行通常说明混进了 IO 或状态管理，那部分应该拆出去。

**强制 15 · 按架构分层拆，不按文件类型拆**：不允许出现 `utils.js`、`helpers.js`、`common.js`、`misc.js` 这类**无业务含义的垃圾桶文件**。要拆成 `usage-stats.mjs`、`zstd-frame.mjs` 这种**按职责命名**的模块。

**强制 16 · 目录深度不限**（用户拍板）：不限制嵌套层数，但**每层目录名必须有业务含义**，不得出现 `a/b/c/`。

#### 3.1.2 架构已定的模块拆分表

实施时**逐模块落地**，不得把多个模块塞进一个文件：

### 3.2 依赖管理（强制）

- **强制 17**：运行时依赖 **必须为 0**。任何 `dependencies` 新增须先经用户确认。
- **强制 18**：开发依赖仅限：`eslint`。不得引入测试框架（用 Node 内置 `node:test`）。
- **强制 19**：呈现层**禁止** `require`/`import` 任何 `@deepseek-ai/` 包（架构铁律 A-1）。
- **强制 20**：纯函数模块**仅**依赖 Node 内置（架构铁律 A-3）。
- **强制 21**：不得出现循环依赖。

## 四、第三层 · 质量门禁

七道闸门，全部可机械化执行。脚本放 `tools/`，步骤 9 落地。

| # | 闸门 | 命令 | 通过标准 |
|---|---|---|---|
| 1 | 语法检查 | `node --check <file>` | 全部通过（零构建方案下替代「构建」闸门） |
| 2 | Lint | `npx eslint .` | 0 error，0 warning |
| 3 | 单元测试 + 覆盖率 | `node --test tests/` | 全绿；纯函数模块覆盖率 ≥ 80% |
| 4 | 密钥扫描 | `node tools/scan-secrets.mjs` | 0 命中 |
| 5 | 依赖扫描 | `node tools/scan-deps.mjs` | 运行时依赖 = 0 |
| 6 | 规范扫描 | `node tools/scan-rules.mjs` | 行数/分层/命名 0 违规 |
| 7 | 正文守门器自检 | `node tools/check-reply.mjs --selftest` | 拦截规则确实能拦、且不误伤 |

**强制 22**：闸门 1–3 是**回归闸门**，每次提交必过。
**强制 23**：闸门 4–7 是**底线闸门**，任一不过则**禁止提交**（预提交钩子拦截）。
**强制 24**：闸门 6 `scan-rules.mjs` 是本规范「强制 13/14/15」的执行者，检查项：

```
- 文件行数 > 上限（500 / 纯函数 300）→ fail
- 出现 utils.js / helpers.js / common.js / misc.js → fail
- 呈现层出现 @deepseek-ai/ → fail
- 纯函数模块出现 require("fs") 等 IO → fail
- 未使用 kebab-case 的 .mjs/.cjs 文件名 → fail
```

**强制 25**：七道闸门的执行记录须落 `tools/gate-log.ndjson`（追加制）。
**强制 26**：「构建」闸门在零构建方案下无对应步骤，**已由闸门 1 语法检查替代**——这一点须在步骤 9 明确记录，避免日后误以为漏了一道。
**强制 27**：测试文件命名 `*.test.mjs`，放 `tests/`，与源码目录**分离**。
**强制 28**：回复正文**禁止**出现内部摘要类内容（`<analysis>` / `<summary>` / 「摘要」「复盘」「回顾」小标题 / 「我读了 X、我改了 Y、接下来做 Z」式流水 / 压缩备忘的固定分节标题）。这类内容只允许出现在工具入参里，不允许出现在发给用户的正文里。
**强制 29**：闸门 7 是强制 28 的执行者——`tools/check-reply.mjs` 维护禁止形态清单，`--selftest` 用正样例（必须被拦）与反样例（必须放行）证明规则没有退化成空壳。**空壳规则比没有规则更危险**：它会让人以为纪律被执行了。

## 五、第四层 · 安全规范

- **强制 30 · 凭证绝不进仓库**：API key、token、私钥、证书、数据库密码、第三方密钥，一律禁止。配套四件套：
  1. `.gitignore` 忽略 `.env*`、`*.key`、`*.pem`、`secrets/`
  2. 凭证走**环境变量**读取，不硬编码
  3. **预提交钩子**扫描暂存区
  4. **CI 闸门**（闸门 4）全量扫描
- **强制 31**：桥**只监听 `127.0.0.1`**，不得绑定 `0.0.0.0`。
- **强制 32**：桥的 HTTP 请求必须校验 `Host` 头为回环，防 DNS rebinding。
- **强制 33**：Electron 窗口一律 `contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`（对齐宿主既有口径）。
- **强制 34**：`preload.cjs` 只暴露**白名单方法**，不得暴露 `ipcRenderer` 本体。
- **强制 35**：渲染进程传入主进程的所有参数必须校验类型与范围（尤其路径与命令行参数）。
- **强制 36**：拉窗时 `delete process.env.ELECTRON_RUN_AS_NODE` 并带 `--no-sandbox`（F6），且**不得**把用户输入拼进命令行。

## 六、AI 协作纪律

五关键点在 AI 参与时的落地条款：

### 6.1 小步迭代 MVP · 端到端切片

- 按功能模块切**端到端切片**，不做「先写一半留一半」
- 每片完成 = 自测 + lint + 闸门过 → 提交 → **立即触发用户验收**
- 允许多次 commit，最后可 squash

### 6.2 模块拆分

见 §3.1。**新增强制，存量逐步治理**。

### 6.3 限制 AI 权限 · 最小改动

- **每次任务先拟《范围声明》交用户确认**：

```
【任务范围声明】
改动文件：<清单>
不改动：<清单>
预期影响：<说明>
```

- 禁顺手重构、禁改 UI 风格、禁改无关逻辑
- 超范围（如发现明显 bug）→ **列影响清单**，经用户确认后再动

**反例清单**（什么算越界）：

| 越界行为 | 为什么越界 |
|---|---|
| 改 A 文件时顺手格式化 B 文件的缩进 | 不是任务范围 |
| 把 `var` 改成 `const`（任务无关处） | 顺手重构 |
| 「顺便」调整了按钮颜色 | 改 UI 风格 |
| 发现一个明显 bug 就直接修了 | 未列影响清单经确认 |
| 给函数加了个「更好用」的新参数 | 改无关逻辑 |

### 6.4 凭证不进仓库

见 §5 强制 30。

### 6.5 报错自查 · 不甩锅复现

用户报 bug 后：

1. **先读代码/日志/报错栈**，定位到文件与行
2. **不猜测**，提出假设须有证据
3. **尽量不烦用户复现**
4. 确需复现时，按四要素提供：

```
前置条件：
复现步骤：
预期结果 / 实际结果：
观察项（日志/截图位置）：
```
