# 切片 4 范围声明

> 依《开发规范》强制 6.3：AI 每次任务先拟范围声明，交用户确认后方可动手。
> 本声明由 AI 起草，**等待用户确认**。

## 一、本片目标

把切片 3 交付的桥能力变成**桌面上看得见的东西**：一条贴屏幕顶边居中的常驻悬浮条。

- 独立 Electron 进程，无边框透明窗口，顶边居中、置顶、不抢焦点、不占任务栏；
- 五元素齐全：鲸鱼 / 状态点 / 会话标题 / token 速度 / 上下文占用；
- 接 `GET /whale/hud`（全量）+ `GET /whale/hud/events`（SSE 增量），桥断则红点 + 全部 `–`；
- 悬停上下文段临时加高到 340px 弹五行详情；
- ≥2 个会话在跑时标题滚筒翻转（停留 3s + 翻转 0.5s，周期 3500ms）；
- 收起成球 / 展开成条，球可拖；
- 右键菜单（隐藏 / 重新加载界面 / 退出）——托盘已移除，这是关掉悬浮条的**唯一途径**。

**本片不装插件进宿主**，不碰 `cordis.patch.yml`。

## 二、四处需要你拍板的决策

### S4-D1 · 几何口径：全程用 DIP，不调 Win32

《轻量架构草案》§3.2 与《references/electron-patterns.md》§三写的是「物理像素走 HWND + `GetWindowRect`，不用 `devicePixelRatio`」。

**但零运行时依赖下做不到**：读 `GetWindowRect` 需要 FFI（node-ffi / koffi），而强制 17 规定运行时依赖必须为 0。

**我的倾向**：全程用 Electron 的 DIP（`screen.getPrimaryDisplay().workArea` + `setBounds`），一次原生调用都不做。

理由：PRD 的 A1 判据本身就是 `x + 588/2 === workArea.x + workArea.width/2` —— 判据里的 `workArea` 就是 DIP，而 `setBounds` 收的也是 DIP，**两侧同量纲，居中计算是自洽的**。需要物理像素的场景只有一个（判定主屏真实分辨率 2560×1440），而居中这件事根本用不到它。

代价：这是**对架构草案的一处偏离**，须在 STATUS 与汇报页写明「几何未走 HWND，理由与影响」。

### S4-D2 · 统计内核：悬浮条不复制 `usage-stats.mjs`

架构草案 §3.2 列了 `whale-hud/lib/usage-stats.mjs`（与桥同源，用于「校验桥的数据是否自洽」）。

**我的倾向：不复制。**

- 分层规则不允许呈现层依赖桥的内部模块，要拿到就只能是物理拷贝；
- 拷贝一份纯函数 = 两份维护、两份可能不一致，直接违反「单一事实源」；
- 而它算出来的值**本来就不用于显示**（架构草案自己写明「只用于校验，不替代桥」），也就是它的产出无处可去。

代价：放弃「桥数据自洽性校验」这一层。降级原则「宁可显示 `–` 不显示错的数」仍然成立——桥没给数就显示 `–`，不需要本地算一份来对照。

若你要求保留副本，我就按架构草案物理拷一份，并在汇报里标注双份维护的风险。

### S4-D3 · 验收深度：是否自建最小 CDP 客户端做真窗口实测

PRD §8.1 的 A1–A11 判据大量依赖 CDP（`Runtime.evaluate`、`Runtime.exceptionThrown`、派发合成鼠标事件）。零依赖下没有 `chrome-remote-interface` 可用。

**我的倾向：自建一个最小 CDP 客户端**，只放 `tools/`（工程工具层，不进产品代码），只实现验收需要的三件事：列 target、发 `Runtime.evaluate`、订阅 `Runtime.exceptionThrown`。RFC6455 客户端帧手写约 120 行。

**严格遵守 PRD 5.6**：`--remote-debugging-port=9334` 就是悬浮条自己的渲染进程，**永不对它发 `Page.navigate`**。

| 判据 | 本片能否自动验 |
|---|---|
| A4 五元素齐全 | ✅ CDP 查 DOM + `offsetWidth > 0` |
| A8 收展 DOM 归属 | ✅ CDP 查 `whaleBtn.parentElement` |
| A11 无控制台报错 | ✅ CDP 订阅 `exceptionThrown` |
| A1 顶边居中 | ⚠️ 主进程日志打印 bounds，与 workArea 对照 |
| A5 悬停加高 | ⚠️ 需派发 `mouseenter`，本片若时间不够转为人工看 |
| A6/A7 滚筒时序 | ⚠️ 渲染层埋点 `window.__hudTiming`，能采就采 |
| A2/A3 焦点与任务栏 | ❌ 需 Win32（`GetForegroundWindow` / UIA 枚举），本片人工确认 |
| A9/A10 图标坐标与拖动 | ❌ 同上，人工确认 |

若你选择「不建 CDP 客户端」，本片只做代码级自检 + 你自己起窗口肉眼看，A4/A8/A11 就不算实测通过，我会在汇报里如实标注「未实测」。

### S4-D4 · F6 完成提醒与 F7 右键菜单是否本片做

**我的倾向：都做。**

- F7 右键菜单不是可选装饰——托盘已移除，没有它就没有关掉悬浮条的办法；
- F6 完成提醒（标题 + 2 秒位移震动）体量小，且 PRD 明确「震动是位移类不是脉冲」，顺手做掉避免后面回补。

### S4-D5 · 点鲸鱼唤起小窗，而小窗还没写

PRD F2①：单击鲸鱼唤起小窗。`whale-window/` 是切片 5。

**做法**：照常发 `POST /whale/open`，桥返回 `entry-missing` 时悬浮条**红闪并落真实原因**，不静默、不假装成功。这条降级路径本片可测（桥已在切片 3 验过同样的响应）。

## 三、新增文件

### 产品代码（`whale-hud/`）

| 文件 | 职责 | 行数预算 |
|---|---|---|
| `main.cjs` | Electron 入口与生命周期编排：`app.setPath('userData')`、就绪后建窗、IPC 注册 | ≤300 |
| `lib/window.cjs` | 窗口创建（无边框/透明/置顶/skipTaskbar）与 P1/P2/P3 三形态切换 | ≤500 |
| `lib/geometry.cjs` | 几何常量与居中/收展布局计算（纯 DIP，见 S4-D1） | ≤300 |
| `lib/state.cjs` | 展开 / 收起 / 球形态状态机；悬停进入 P3 的进入与缩回判定 | ≤500 |
| `lib/ipc.cjs` | 主进程侧 IPC 处理（openWindow / ballMode / hover / hide / quit / reload） | ≤300 |
| `preload.cjs` | `window.hud` 受控通道（白名单，不暴露 `ipcRenderer` 本体） | ≤200 |
| `renderer/index.html` | 结构 + CSP（**必须放行 `'self'`**，否则 hud.js/hud.css 被静默拦截） | ≤120 |
| `renderer/hud.css` | 样式（全部数值取自《前端设计规范》，不自创） | ≤500 |
| `renderer/hud.js` | SSE 接入 + 五元素渲染 + 降级（桥断 → 红点 + `–`） | ≤500 |
| `renderer/carousel.js` | 多会话轮播（F4），含 `reelGen` 代际号与 `rolling` 看门狗 | ≤500 |
| `run.ps1` | 启动脚本（`--no-sandbox`，必用） | — |
| `package.json` | 无 `dependencies` | — |

**为什么几何与状态机分开**：几何是「算数」，状态机是「记状态、定转换」。两者的改动原因完全不同——改缩放适配只动几何，改交互只动状态机。挤一起会让「加一种形态」变成在两个关注点之间来回跳。

**为什么 `carousel.js` 单独**：滚筒是整份代码里最容易出错的一段（双定时器 + DOM 双缓冲 + 互斥锁），单独成文件才能让它的单测只盯着时序，不被渲染逻辑干扰。

### 工程工具（`tools/`，不进产品）

| 文件 | 职责 |

| 文件 | 测什么 |

## 七、风险

| 风险 | 应对 |
|---|---|
| Electron 起不来（缺 `--no-sandbox` 崩 `0x80000003`） | `run.ps1` 与 `bridge-dev-server` 的 spawn 都显式带 `--no-sandbox`；单测断言 args |
| 模块顶层调 `app.getPath()` 原生崩溃 `0xFFFF7003` | 先 `app.setPath('userData', ...)`；日志路径惰性 `ensureLogPaths()`；不在顶层读 |
| CSP 只写 `unsafe-inline` 导致 hud.js 被静默拦截 | index.html 的 CSP 必须含 `'self'`；写成契约测试的断言项 |
| 滚筒闪假标题（`swapAt` 顺序反了） | 严格照规范：`swapAt` 只改 `front`；下半程先清类再改 `back`；契约测试断言 `faceB` 在 `faceF` 之前 |
| 收起后图标被 `scaleX(0)` 压成 0 宽 | 收起时物理挪 `#whaleBtn` 到 `document.body`，用 `whaleHome = {parent, next}` + `insertBefore` 还原；处理「已在 body 里」的情况 |
| 渲染层 `node --check` 查不出 TDZ | 真起窗口看 `exceptionThrown`；不靠离线检查下结论 |
| 本片改动面大（十来个文件） | 分两批提交：先「主进程 + 窗口 + 几何/状态机」，再「渲染层 + 滚筒 + 验收」；每批都过闸门 |
