# 切片 5 范围声明

> 依《开发规范》强制 6.3：AI 每次任务先拟范围声明，交用户确认后方可动手。
> 本声明由 AI 起草，**等待用户确认**。

## 一、本片目标

交付三件套里的第二件：**小窗** —— 一扇常驻桌面、能真正跟 DSH 会话对话的窄窗。

- 独立 Electron 进程，无边框 + 真圆角 + CSS 阴影，内容 460×678（窗口 492×710）；
- 右侧居中、可拖可缩放、位置与置顶状态记忆到 `window-state.json`；
- 接 `GET /whale/panel`（全量）+ `GET /whale/events`（SSE 增量），渲染消息流；
- 能发消息进**真会话**（`POST /whale/send`）、排队语义、中断（红方块）；
- 斜杠命令面板、权限三档、任务坞、状态条；
- 切会话三档标签（当前 / 可切换 / 历史）；
- 崩溃自愈：渲染进程挂了自动重载，超 3 次落兜底页。

**同时回补切片 3 欠的三条验收**：C7（拉窗可用）、C8（拉窗复用）、C12。

## 二、先分组：本片分三批，每批都过闸门

小窗比悬浮条大得多（PRD 十三个功能点、验收十四条），一次做完既难验也难回退。
按「先能站住 → 再能说话 → 再能切换」切三批：

| 批次 | 内容 | 完成后的可验状态 |
|---|---|---|
| **A** | 主进程（窗口/几何/持久化/崩溃自愈）+ preload + 顶栏 + 会话标题行 + 骨架页面 | 窗口起得来、能看到顶栏与标题、能拖、位置记得住；**回补 C7/C8/C12** |
| **B** | 消息流 + 输入区 + 发送/排队/中断 + 状态条 | 能真的跟会话对话（B5/B6/B7） |
| **C** | 斜杠面板 + 权限三档 + 任务坞 + 切会话 + 各面板 + 资料抽屉 | 功能齐（B8/B9/B10） |

每批 = 自测 + 七道闸门全过 → 提交 → 你验收。**不攒到最后一起交。**

## 三、需要你拍板的四处

### S5-D1 · 物理像素：本片同样不走 PowerShell 子进程

《小窗-PRD》5.5 写：本机缩放 113% 而 `devicePixelRatio` 报 1，故用
`getNativeWindowHandle()` 拿 HWND，再**起一个 PowerShell 子进程调 `GetWindowRect`** 读物理值。

**我的倾向：不做，全程用 DIP。**

理由（与切片 4 的 S4-D1 同源）：
- 每次几何查询起一个 PowerShell 进程，在小窗这种「拖动/缩放高频」的场景里代价极高；
- PRD 说这个偏差影响的是「物理像素与逻辑像素的换算」，而 `setBounds` 收的本身就是 DIP——**两侧同量纲就自洽**；
- 真正会受影响的只有 B2（四角像素 alpha）与 B3（阴影像素），而这两条本就要**截图取证**，截出来的就是物理像素，不需要再换算一次。

代价：B2/B3 的图像判据由「主进程算好物理值再比」改为「直接对截图采样」。逻辑等价，少一层可能出错的手工换算。

### S5-D2 · 验收探针：复制切片 4 的纪律，还是另起一套？

**我的倾向：复用同一套纪律，不另起。**

具体：小窗也把装配抽成一个 `boot()`，产品入口与探针共用；探针只许模拟用户输入，不得调用 `loadFile`/`setBounds`/`show` 等产品方法；探针必须先验「页面真加载了」再验其余项。

这条不是可选项——切片 4 已经用一次事故证明：**探针替产品干活 → 全绿的产品是全白的**。新增的 `probe-discipline` 测试会扩到覆盖小窗探针。

### S5-D3 · 窗口状态记忆的落盘位置

PRD 说存 `window-state.json`，目录说在 `whale-window/.userdata/`。

**我的倾向：落在 `.userdata/window-state.json`**，与日志同目录，且整体被 `whale-window/.gitignore` 忽略。

理由：状态文件是运行数据，不该混在源码目录里；小窗的 `.userdata` 已经存在（userData 指向它），放一起便于用户「想重置就删掉整个目录」。

### S5-D4 · 崩溃自愈的重载上限

PRD 写 `RENDERER_RELOAD_MAX = 3`，而《references/electron-patterns.md》的示例写 `crashCount <= 2`（即最多 reload 两次，第三次落兜底页）。

两处不一致，差一次。

**我的倾向：按 PRD 的 3**（PRD 优先级最高，架构草案与 references 都低于它），即**前 3 次重载、第 4 次落兜底页**。

## 八、风险

| 风险 | 应对 |
|---|---|
| 缩放系数施加两次（PRD 记过：曾变 1.1³≈1.33） | 单测钉住「缩放只在一个地方施加」；`toWindowSize()` 只加边距 |
| `SHADOW_PAD` 与 `--shadow-pad` 不一致 → 阴影被硬切 | 契约测试断言两处相等 |
| 崩溃自愈把「正常退出」也算成崩溃 | 只在 `render-process-gone` 计数；`did-finish-load` 清零 |
| 位置记忆每次重启放大一次 | 记忆值直接当窗口尺寸用；只在**无记忆值**时才由内容尺寸换算 |
| 无边框窗口的拖动与按钮点击打架 | 顶栏为拖拽区，按钮必须 `no-drag`；探针驱动 drag 通道而非合成事件 |
| 本片规模大（十余文件） | 已分三批，每批独立过闸门与验收 |

## 九、本片不做的事（防止范围蔓延）

- 不做页面内小鲸鱼按钮（切片 6）
- 不装插件进真实宿主
- 不做桌面毛玻璃（实测做不到，PRD 5.9）
- 不做孤儿防护（PRD 5.6 明令不得加回）
- 不做语音输入（刻意置灰，二期）
- 不做托盘（已移除，不得加回）
- 不走 PowerShell 子进程读物理像素（S5-D1）
