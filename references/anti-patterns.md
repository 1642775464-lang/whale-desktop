# references · 反例清单

> 本文件列出**具体的、可辨认的错误做法**。看到自己正在做下列任何一条，立即停下。
> 配套：《开发规范》§3.1（模块拆分）、§6.3（最小改动）。

---

## 一、模块拆分反例（对应强制 13/14/15）

### ❌ 反例 1：垃圾桶文件

```
lib/utils.js          ← 无业务含义
lib/helpers.js
lib/common.js
lib/misc.js
```

问题：这类文件一旦存在，就必然持续吸收「不知道放哪」的代码，最终变成千行巨物，且依赖关系失控。

**正确**：按职责命名。`usage-stats.mjs`（算统计）、`zstd-frame.mjs`（解 zstd）。

---

### ❌ 反例 2：一个文件承担多个职责

```js
// main.cjs —— 同时干四件事
function createWindow() { ... }      // 窗口管理
function calcGeometry() { ... }      // 几何计算
function handleHover() { ... }       // 状态机
function persistState() { ... }      // 持久化
```

问题：无法单测任一职责；改几何要动窗口文件；500 行上限很快突破。

**正确**：拆成 `lib/window.cjs`、`lib/geometry.cjs`、`lib/state.cjs`。

---

### ❌ 反例 3：用注释分隔职责

```js
// ========== 折叠逻辑 ==========
... 200 行 ...

// ========== 统计逻辑 ==========
... 200 行 ...

// ========== HTTP 路由 ==========
... 200 行 ...
```

问题：注释分隔**不是**模块拆分。600 行的文件里放三个职责，仍然违反单一职责。

**正确**：三个独立文件。

---

### ❌ 反例 4：为「省事」合并纯函数

```js
// lib/stats.mjs —— 把折叠和统计放一起
export function foldEvents(events) { ... }
export function sumUsage(usages) { ... }
```

问题：两者都可单测，但混在一起后，测试文件也只能混着测，失败时定位困难。

**正确**：`fold.mjs` 与 `usage-stats.mjs` 分开。

## 二、最小改动反例（对应强制 6.3）

| ❌ 越界行为 | 为什么越界 |
|---|---|
| 改 A 文件时顺手格式化了 B 文件 | 不是任务范围 |
| 把任务无关处的 `var` 改成 `const` | 顺手重构 |
| 「顺便」调整了按钮颜色 | 改 UI 风格 |
| 发现明显 bug 就直接修了 | 未列影响清单经用户确认 |
| 给函数加了「更好用」的新参数 | 改无关逻辑 |
| 把 `function f(){}` 改成箭头函数 | 风格变更，非任务要求 |
| 重排了 import 顺序 | 无关改动 |
| 删掉「看起来没用」的代码 | 未确认，可能是刻意保留 |

**遇到超范围问题的正确做法**：

```
【超范围发现】
位置：lib/xxx.mjs:123
现象：<具体现象>
影响：<不改会怎样 / 改会影响哪些文件>
建议：<改 / 不改>
请确认。
```

## 三、降级原则反例（对应《边界与 NFR》四条原则）

| ❌ | 为什么错 | ✅ |
|---|---|---|
| 桥不可用时显示 `0%` 占用 | 假装有数据 | 显示 `–` |
| 某个会话数据坏了，整个悬浮条不渲染 | 局部故障扩散 | 该会话显 `–`，其余正常 |
| 没有新事件时仍让速度条动 | 假装能动 | `frozen = true`，静止 |
| 出错后静默失败，无任何提示 | 用户无出口 | 显示错误态与重试入口 |
| 落盘无 `cacheWriteTokens` 就填 0 并当成真实值 | 虚构数据 | 标记为「不可得」 |

## 四、宿主口径反例

| ❌ | 为什么错 | ✅ |
|---|---|---|
| 中断用 `agent.cancel({kind:"user"})`（不传 keepInbox） | 会清空用户待发队列 | `{ keepInbox: true }`（对齐 `dsh-api-session-controller:994-1000`） |
| 整体解压 zstd | 只出第一帧 | 逐帧解 |
| 用 `devicePixelRatio` 算物理尺寸 | 本机实测报 1，但缩放 113% | HWND + `GetWindowRect` |
| 用 `totalTokens` 当上下文占用 | 它含缓存读 | `pressureFrom(usage)` |
| 呈现层 `require('@deepseek-ai/...')` | 违反架构铁律 A-1 | 只走 HTTP |
| 桥绑 `0.0.0.0` | 暴露到局域网 | 只绑 `127.0.0.1` |
| 拉窗时不删 `ELECTRON_RUN_AS_NODE` | Electron 以 Node 模式启动，无窗口 | 启动前 delete |

## 五、工程反例

| ❌ | ✅ |
|---|---|
| 提交前不跑闸门 | 闸门 1–3 必过 |
| 测试和源码混在同一目录 | `tests/` 分离 |
| 引入 lodash 等运行时依赖 | 运行时依赖 = 0 |
| 用 Jest/Mocha | `node:test` |
| 硬编码端口 | 常量 `PORT = 19387` |
| 把密钥写进代码「暂时用一下」 | 环境变量读取 |
| 行尾混用 CRLF/LF | 统一 LF |
